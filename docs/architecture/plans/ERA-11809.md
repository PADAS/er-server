# ERA-11809 — Server-side vector tile service for Events

> Implementation is delegated to the `backend-developer` agent.

## Context

Parent story **ERA-8350 "Vector tile service - events"**. Today the only way the
client renders events on the map is the paginated GeoJSON list API
(`/activity/events/geojson/`), which forces the browser to fetch, hold, and
re-render large feature collections. We already serve **SpatialFeatures** and
**ObservationSegments/Subjects** as Mapbox Vector Tiles (MVT) generated in
PostGIS via `ST_AsMVT`, with a dedicated Redis tile cache. ERA-11809 extends
that same infrastructure to **Events**, so the client can render events as
vector tiles (server-side tiling, binary PBF, far less client-side processing).

Per the ticket the events tile endpoint must:
- Serve events as MVT, **following the `SpatialFeatureLayer` pattern**.
- Honor the **full `/activity/events` filter surface** in the request URL
  (`event_type`, `state`, `event_ids`, `updated_since`, `is_collection`/
  `exclude_contained`, `bbox`, the JSON `filter` spec, category-permission and
  related-subject scoping) — materially richer than the SpatialFeature filterset.
- Use a Redis cache with a **very short TTL (3–5 min)**, keyed by user + full
  request URL.
- **Bust a user's cached tiles** when their token is deleted or their
  permissions change.
- Be written so the layer can later become a **multi-class layer (events +
  subjects)** — do not preclude that.

### Confirmed design decisions
1. **Filtering**: reuse the existing events DRF filter backends in the layer —
   identical semantics to `/activity/events`, no duplicated logic.
2. **Cache key**: reuse `build_tile_cache_key` (hashed user-id + tile z/x/y +
   hash of the full query string) **plus a per-user version counter** bumped on
   token-delete / permission-change. No raw tokens in Redis; survives token
   rotation; O(1) busting. The query hash already captures all filters.
3. **Geometry scope**: **points now** (`Event.location`), structured so
   `EventGeometry` polygons/lines can be added as a follow-up.

## Existing infrastructure to reuse (do not reinvent)

- `DRFMVTView` — `das/das_server/views.py` (base MVT view with DRF auth +
  `permission_classes`, `layer_classes`).
- `SpatialFeatureLayer` — `das/mapping/vector_layers.py` (the pattern to follow:
  `tile_fields`, `_get_geometry_field()` → `Transform(..., 3857)`, `get_queryset`
  with annotations). `SubjectVectorLayer` (`das/observations/vector_layers.py`)
  is the reference for a **request-aware, permission-filtered** layer (takes
  `request` in `__init__`).
- `ObservationSegmentTileView` — `das/observations/views/vector_tiles_segments.py`
  is the closest reference: per-tenant cache versioning, query-param filterset,
  tile-coordinate validation, ETag/304, `Cache-Control`/`Vary`, `X-Cache`,
  multi-class `layer_classes`.
- Cache utilities — `das/utils/cache.py`: `build_tile_cache_key`,
  `get_vector_tile_cache`, `get_effective_cache_version`, and the per-tenant
  versioning pattern (`get_observation_segment_cache_version` /
  `bump_observation_segment_tile_version`) to mirror for a **per-user** counter.
- Events filtering — `das/activity/filters.py`: `EventPermissionsFilter`,
  `EventListFilter`, `EventSubjectsFilter` (all `BaseFilterBackend`, use only
  `(request, queryset)` — `view` is unused, so they run cleanly from a layer).
- Events queryset methods — `EventFilteringQuerySet` (`das/activity/models.py`):
  `by_category`, `by_location`, `by_state`, `by_event_type`, `by_bbox`,
  `by_event_filter`, etc. Tenant isolation is automatic via `TenantManagerMixin`.
- EventType render attributes — `EventType.icon_id` / `image_url`, priority→color
  mapping `Event.image_basename()` / `CONVERSION` in `das/activity/models.py`;
  GeoJSON precedent `make_feature` in `das/activity/serializers/helpers.py` for
  the property set the client expects.

## Implementation

### 1. `EventVectorLayer` — `das/activity/vector_layers.py` (new)
Subclass `vectortiles.VectorLayer`, modeled on `SubjectVectorLayer`.

- `model = Event`, `id = "events"`, `min_zoom`/`max_zoom` (match 3/24).
- `__init__(self, request=None)`: store `self.request` (request set by the view
  after `permission_classes` run, same as the subject/segment layers).
- `_get_geometry_field()`: `Transform(F("location"), 3857)` (on-the-fly; events
  are points and churn constantly under a 3–5 min TTL, so a precomputed
  web-mercator column like SpatialFeature's is not warranted here — note this as
  a deliberate trade-off and a future option if profiling shows need).
- `tile_fields`: the property set the client needs for styling without extra
  round-trips — **coordinate the final list with the front-end team** (ticket
  requirement). Starting set, mirroring `make_feature`/`EventGeoJsonSerializer`:
  `id`, `serial_number`, `event_type` (value), `event_category`, `priority`,
  `state`, `title`, `event_time`, `updated_at`, `is_collection`, plus resolved
  `image`/`icon_url` and `color` (priority+state → color via the existing
  `CONVERSION` logic, expressed as SQL `Case/When` so `ST_AsMVT` emits it).
  Format timestamps in SQL (reuse/clone the `_ISOTimestamp` Func from
  `observations/vector_layers.py`) so Mapbox GL gets sortable strings.
- `get_queryset()`:
  1. `qs = Event.objects.all()` (tenant auto-scoped) → `.filter(location__isnull=False)`.
  2. **Apply the events filter backends in order**, reusing them verbatim:
     `EventPermissionsFilter().filter_queryset(self.request, qs, view=None)`, then
     `EventListFilter(...)`, then `EventSubjectsFilter(...)`. This yields full
     filter + permission parity with `/activity/events`.
  3. `select_related("event_type", "event_type__category")` and `.annotate(...)`
     the `geom` + `tile_fields` expressions.
- Superuser path: backends already short-circuit appropriately; mirror the
  subject layer's `is_superuser` handling where relevant.

### 2. `EventTileView` — `das/activity/views/events/vector_tiles.py` (new)
Modeled on `ObservationSegmentTileView`.

- `class EventTileView(DRFMVTView)`, `layer_classes = [EventVectorLayer]`
  (list form — leaves the door open to `[EventVectorLayer, SubjectVectorLayer]`
  for the future multi-class layer).
- `permission_classes`: an `EventsPermissions`-style class + a tenant/host guard
  analogous to `ObservationSegmentTilePermission` (validate host→tenant, then
  require event read access). `get_queryset()` returns `Event.objects.none()`
  for the DRF model-permission machinery (tiles come from `layer_classes`).
- `content_type = "application/vnd.mapbox-vector-tile"`.
- **Cache TTL (ticket)**: `cache_timeout_seconds = 300` (5 min) server-side;
  client `max-age`/`stale-while-revalidate`/`stale-if-error` ≈ 180–300s.
- `get(self, request, z, x, y)`: copy the `ObservationSegmentTileView.get`
  structure — validate tile coords (z 0–24, x/y in range → 400), build the cache
  key with the **per-user** version (below), ETag/304 handling, serve-from-cache,
  on miss instantiate `self.layers = [lc(request=request) for lc in layer_classes]`
  and `_get`, then set `Cache-Control`/`ETag`/`Vary`/`X-Cache`. Invalid filter
  params raised by the reused backends (`ParseError`/`BadRequestAPIException`)
  propagate to DRF → 400.
- Add a `CustomSchema` subclass documenting the supported query params (reuse the
  events query-param descriptions).

### 3. Per-user cache version + busting — `das/utils/cache.py`
Mirror the per-tenant observation-segment versioning, but per user:

- `get_user_tile_version(tenant_id, user_id) -> int` and
  `bump_user_tile_version(tenant_id, user_id) -> None` (Redis `add`+`incr`, no
  TTL, same defensive fallback as `bump_observation_segment_tile_version`). Key:
  `user_tile_ver:{tenant_id}:{user_id}` (explicit tenant prefix — the
  `vector_tiles` alias keys are namespaced by hand, as the obs-segment code does).
- `get_event_tile_cache_version(tenant_id, user_id) -> str`:
  `f"{get_effective_cache_version()}-u{get_user_tile_version(...)}"`. The view
  passes this as `cache_version=` to `build_tile_cache_key`, so a bump
  invalidates **only that user's** event tiles instantly. Export new names in
  `__all__`.

### 4. Cache-busting signals — `das/activity/signals.py` (or `accounts/signals.py`)
Per the chosen **per-user best-effort** strategy (3–5 min TTL is the backstop):

- **Token deletion** → `post_delete` on `AccessToken` (oauth2_provider): bump
  `instance.user`. ⚠️ queryset/bulk token revocations bypass `post_delete`;
  document that the short TTL covers those.
- **Direct membership change** → `m2m_changed` on the `PermissionSet.members`
  through model (`user.permission_sets`): bump each affected user on
  `post_add`/`post_remove`/`post_clear`.
- **Permission-set contents change** → `post_save`/`post_delete` on
  `PermissionSetPermission`: bump all `members` of that set (best effort).
- **Documented gaps (rely on TTL backstop)**: group-mediated permission sets and
  deep hierarchy (ancestor) edits are not chased per-user. Call these out
  explicitly so the limitation is intentional and visible.
- Ensure the chosen `signals` module is imported from the app's `AppConfig.ready()`.

### Freshness & realtime (event data changes)
The cache-busting in §3/§4 is for **identity/permission** changes, **not** event
data changes. This section defines how a newly created/edited/deleted event
reaches the map, so it isn't relitigated in review.

- **Tiles are bulk rendering; the realtime socket is the source of freshness.**
  This mirrors the observation-segment/subject tiles, whose code comment states
  realtime positions come via WebSocket and *"these tiles are primarily for
  efficient bulk rendering, not the source of truth for freshness."* Events
  already publish over pubsub on commit in `das/activity/signals.py`
  (`das.event.new` on create, `das.event.update`, `das.event.delete`); the web
  client renders those immediately, layered over the tiles.
- **A new event does NOT bust the tile cache.** On the next map move, panning to
  not-yet-cached tiles/filters is a cache miss → fresh tile that includes the new
  event; panning back to an already-cached tile serves stale until the short
  (3–5 min) TTL expires. New events appear promptly regardless via the socket.
- **Do NOT bump a tile version on event create.** Events are the hot path; a
  per-tenant bump on every create would invalidate all users' event tiles
  tenant-wide on every new event and collapse the cache hit rate — which is
  exactly why the obs-segment design excludes creates.
- **Optional: per-tenant event-tile version bumped on update/delete only.** Add
  `get_event_tile_data_version(tenant_id)` / `bump_event_tile_data_version(tenant_id)`
  in `utils/cache.py` (same `add`+`incr` pattern as the obs-segment version) and
  fold it into `get_event_tile_cache_version(...)` alongside the per-user
  component. Bump it from the existing `Event` `post_save` (when `created` is
  False) and `post_delete` handlers in `activity/signals.py`. Effect:
  edits/resolutions/deletions refresh fast tenant-wide; creates still rely on
  socket + TTL. Net cache impact is bounded because edits/deletes are far rarer
  than creates.

### 5. URL — `das/activity/urls.py`
Add `events/tiles/(?P<z>\d+)/(?P<x>\d+)/(?P<y>\d+)\.pbf` → `EventTileView`,
name `event-tiles`, mirroring the spatialfeature/observation tile URL style.

## Tests (`das/activity/tests/`)
Follow `observations/tests/test_vector_tiles.py`:
- Tile returns 200 + `application/vnd.mapbox-vector-tile`; decoded MVT contains
  the expected events and `tile_fields` (use `mapbox-vector-tile` decode as the
  existing tests do).
- **Filter parity**: `state`, `event_type`, `bbox`, JSON `filter` each scope the
  tile identically to `/activity/events`.
- **Permissions**: a user without a category read-perm gets no events of that
  category; related-subject scoping respected; tenant isolation (no cross-tenant
  events) — see `er-developer:tenant-isolation`.
- **Caching**: HIT/MISS via `X-Cache`; ETag → 304; cache key varies by query
  string and by user.
- **Busting**: `bump_user_tile_version` (and each signal) invalidates that user's
  tiles but not another user's; invalid `bbox`/`filter` → 400; bad tile coords → 400.
