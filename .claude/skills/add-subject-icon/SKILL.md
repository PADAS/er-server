# Add Subject Icon Skill

This skill guides you through uploading and configuring icon images for subject subtypes in the EarthRanger/DAS system.

## Icon Conventions

### Gender-Specific Icons
Subject icons can be male and female variants:
- **Naming**: `{value}-male.svg` and `{value}-female.svg`
- **Visual convention**:
  - Male animals face LEFT
  - Female animals face RIGHT
- **Parser**: System looks for `-male` and `-female` in filenames to select appropriate icon
- **Value**: The `{value}` matches the SubjectSubType.value field (e.g., `donkey`, `elephant`, `vicuna`)

### Storage Location
All subject icons are stored in: `das/observations/static/`

### File Format
- SVG format preferred for scalability
- Keep file size reasonable (< 100KB)

## Workflow

When this skill is invoked, follow these steps:

### 1. Gather Information
Ask the user for:
- **Subject subtype name** (e.g., "Donkey", "Vicuna")
- **Subject subtype value** (slug, e.g., "donkey", "vicuna") - this becomes the filename prefix
- **Icon file paths** (for both male and female variants if applicable)
- **Subject type** (e.g., "wildlife") - usually defaults to "wildlife" for animals

### 2. Validate the Icon Files
- Check that files exist and are valid SVG format
- Verify naming follows convention: `{value}-male.svg` and `{value}-female.svg`
- Verify visual convention: male faces left, female faces right
- Check file size is reasonable (< 100KB per file)
- Confirm icons are clearly distinguishable and appropriate for the subject

### 3. Copy Icon Files
Copy the icon files to the correct location:
```bash
cp <source-male.svg> das/observations/static/{value}-male.svg
cp <source-female.svg> das/observations/static/{value}-female.svg
```

Example:
```bash
cp vicuna-male.svg das/observations/static/vicuna-male.svg
cp vicuna-female.svg das/observations/static/vicuna-female.svg
```

### 4. Create Migration
Create a new migration file to add the SubjectSubtype entry:

**Location**: `das/observations/migrations/XXXX_{name}.py`

**Template**:
```python
# Generated by Django 3.2.25 on YYYY-MM-DD HH:MM

from django.db import migrations

from observations.migration_utils import TenantSubjectSubTypeLoader

subject_subtype_loader = TenantSubjectSubTypeLoader(subject_type_value="wildlife").add_subject_subtype(
    display="{Display Name}",
    value="{value}",
)


class Migration(migrations.Migration):

    dependencies = [
        ("observations", "{previous_migration}"),
    ]

    operations = [
        migrations.RunPython(
            code=subject_subtype_loader.load,
            reverse_code=migrations.RunPython.noop,
        )
    ]
```

**Example** (see `das/observations/migrations/0193_donkey.py`):
```python
from django.db import migrations
from observations.migration_utils import TenantSubjectSubTypeLoader

subject_subtype_loader = TenantSubjectSubTypeLoader(subject_type_value="wildlife").add_subject_subtype(
    display="Donkey",
    value="donkey",
)

class Migration(migrations.Migration):
    dependencies = [
        ("observations", "0192_whale_shark_icon"),
    ]

    operations = [
        migrations.RunPython(
            code=subject_subtype_loader.load,
            reverse_code=migrations.RunPython.noop,
        )
    ]
```

**Important**:
- Migration number should be sequential (find latest migration number first)
- Update `dependencies` to point to the previous migration
- Use `TenantSubjectSubTypeLoader` for tenant-aware loading

### 5. Update initial_data.json
Add an entry to `das/das_server/fixtures/initial_data.json`:

**Template**:
```json
{
  "model": "observations.subjectsubtype",
  "fields": {
    "created_at": "YYYY-MM-DDTHH:MM:SS.sssZ",
    "updated_at": "YYYY-MM-DDTHH:MM:SS.sssZ",
    "value": "{value}",
    "display": "{Display Name}",
    "subject_type": [
      "wildlife"
    ],
    "ordernum": null
  }
}
```

**Example** (donkey entry):
```json
{
  "model": "observations.subjectsubtype",
  "fields": {
    "created_at": "2025-05-04T23:41:00.000Z",
    "updated_at": "2025-05-04T23:41:00.000Z",
    "value": "donkey",
    "display": "Donkey",
    "subject_type": [
      "wildlife"
    ],
    "ordernum": null
  }
}
```

**Important**:
- Use current timestamp for created_at and updated_at
- Add this entry to the appropriate location in the JSON array (typically with other SubjectSubtype entries)
- Ensure valid JSON formatting (check commas)

### 6. Verify and Test
- Confirm icon files are in `das/observations/static/`
- Check naming matches the value field: `{value}-male.svg`, `{value}-female.svg`
- Verify migration file is created correctly
- Verify initial_data.json entry is added correctly
- Run migration: `python manage.py migrate`
- Test icon display in the UI

## Key Considerations

- **Multi-tenancy**: TenantSubjectSubTypeLoader handles tenant-aware loading across all tenants
- **File naming**: Must match exactly: `{value}-male.svg` and `{value}-female.svg`
- **Visual convention**: Male faces LEFT, female faces RIGHT
- **Subject type**: Most animals use "wildlife" as the subject_type_value
- **Migration sequence**: Ensure migration number is sequential and dependencies are correct

## Complete Example: Adding Vicuna Icons

1. **User provides**: vicuna-male.svg and vicuna-female.svg files
2. **Copy icons**:
   ```bash
   cp vicuna-male.svg das/observations/static/vicuna-male.svg
   cp vicuna-female.svg das/observations/static/vicuna-female.svg
   ```

3. **Create migration** `das/observations/migrations/0194_vicuna.py`:
   ```python
   from django.db import migrations
   from observations.migration_utils import TenantSubjectSubTypeLoader

   subject_subtype_loader = TenantSubjectSubTypeLoader(subject_type_value="wildlife").add_subject_subtype(
       display="Vicuna",
       value="vicuna",
   )

   class Migration(migrations.Migration):
       dependencies = [
           ("observations", "0193_donkey"),
       ]

       operations = [
           migrations.RunPython(
               code=subject_subtype_loader.load,
               reverse_code=migrations.RunPython.noop,
           )
       ]
   ```

4. **Add to initial_data.json**:
   ```json
   {
     "model": "observations.subjectsubtype",
     "fields": {
       "created_at": "2026-01-09T00:00:00.000Z",
       "updated_at": "2026-01-09T00:00:00.000Z",
       "value": "vicuna",
       "display": "Vicuna",
       "subject_type": [
         "wildlife"
       ],
       "ordernum": null
     }
   }
   ```

5. **Run migration**: `cd das && python manage.py migrate`
